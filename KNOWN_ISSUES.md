# Known issues

Defects that **reading the code did not reveal** — found by running it, driving
it, or querying what it stored. Runtime failures, external service behaviour,
environment-specific problems, and anything whose evidence is a browser session
or a database row rather than a file in the repo.

The test is **how a defect was found**, not where it can be seen afterwards. An
entry does not stop belonging here because the two lines responsible are obvious
in source once you know which two — that is hindsight, and hindsight is the
reason an entry is worth writing down rather than a reason to refuse it. KI-05 is
the case in point: `value={page ? pathOf(page) : ""}` reads perfectly well until
you have watched six keystrokes vanish into it.

The exclusion still stands and is a different one: nothing found **by reading**
belongs here. The auditor can find that for itself, and putting it in this file
— which the auditor reads during its gather step — anchors it and defeats the
point of the separate context. That work lives in `audits/`.

The `auditor` subagent reads this during its gather step. The `/audit-fix` loop
updates statuses here as it closes them.

Status values: `open` · `fix attempted` · `verified` · `regressed`
